# 多人协作频道：分工分析

用户之前分析的频道大多是“一个人拍自己”：自拍加固定机位。遇到出镜、掌镜、故事核心分属不同人的频道（家庭、情侣、搭档、团队），用户最关心的就是**分工**：谁出镜、谁拍、视频围着谁转，以及这种分工和单人拍摄有什么不同（用户要求，2026-10-22，Hey KaKa：姐姐出镜、弟弟掌镜、爸爸是故事核心）。这时分工要做成报告的主线，不能只放在器材页里一笔带过。

## 1. 抽帧

`gear_scan.py` 每条视频只有 3 张自动截帧，不够数占比。用：

```bash
python3 $S/frame_sample.py $W/data/<handle> --out $W/collab --every 20 [--top 12] [--proxy socks5://…]
```

它会下载 240p 无声版（每 15 分钟约 20 MB，缓存在 `collab/video/`），每 N 秒截一帧，拼成带 `V<n> mm:ss` 标签的联系表 `collab/sheets/`。V1 是最早的一条，按时间顺序排。视频超过 12 条时，挑最新的、播放最高的、播放最低的各几条。

字幕（创作者上传的英文字幕通常就是旁白原文）：

```bash
yt-dlp -q --skip-download --write-subs --write-auto-subs --sub-langs "en.*,en" --sub-format vtt -o "$W/collab/subs/%(id)s" URL
```

## 2. 逐帧记录

每张联系表逐帧看，记两件事：

- **画面里有谁**（可以多选）：每个角色一列，比如姐姐、弟弟、爸爸、祖辈、朋友，再加空镜。占比 = 出现帧数 ÷ 抽样帧数。
- **主角出镜时谁在拍**：自拍（手臂伸出、广角近脸）、别人拍（跟拍、远景、主角在做事不看镜头）、固定机位、手部特写。

字幕里数每个角色被提到的次数，再摘几句讲“拍视频这件事”的原话，比如谁第一次拿相机、家人看了视频的反应。

结果写进 `collab/roles.json`：逐条的帧数和各角色帧数、`sister_camera` 这类镜头来源统计、原话摘录。

## 3. 要回答的问题和对应页面

都用 deck-json 里已有的页面类型，插在“家庭成员”后面，开一个“家庭协作”分节：

| 问题 | 页面 |
|---|---|
| 每个人是什么角色、各占多少画面 | `cards`：每个角色一张卡片，`statement` 点出和单人拍摄的区别 |
| 逐条视频的分工 | `table`：视频、播放、各角色占比、旁白提到核心人物的次数（竖版用 `portrait` 删列） |
| 哪个角色和播放相关 | `panels`：有某角色出镜的平均播放 vs 没有的平均播放，`box` 写反例和样本量提醒 |
| 谁在拿相机 | `stats4`：主角出镜画面里别人拍 / 自拍 / 固定 / 特写的占比，`bullets` 和单人频道对比 |
| 协作本身怎么变成内容 | `rows`：按视频列出原话里的协作时刻 |
| 和单人拍摄差在哪 | `table`：谁在拍、画面、故事、情感、门槛、风险 |
| 想复制需要什么 | `cards`：讲述者、掌镜人、故事核心、引路人 |

封面副标题、“一页看懂”的发现、“为什么能火”、器材页标题、“启示”页都要改成围绕分工来写。

## 4. 和单人频道对比的数据

不要凭印象写“单人频道都是自拍”。到 `~/youtube-*-report-*/gear.json` 里找之前做过的报告，用它们 `style` 里“别人帮忙拍”的占比做对比。注意之前的数据是每条 3 张自动截帧，这次是固定间隔抽帧，口径不同，要在 note 里写明。

## 5. 写法

- 样本少（< 10 条）时，相关性结论写“供参考”，并给出反例。
- 抽帧统计是人工判断，note 里写清楚“每 N 秒 1 帧、共 X 帧、一帧可多人”。
- 出镜人有未成年人时，按 compliance.md 处理：原话摘录不能带家庭隐私。
